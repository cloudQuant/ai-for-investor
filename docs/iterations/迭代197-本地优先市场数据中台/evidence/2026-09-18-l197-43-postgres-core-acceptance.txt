## 验收驱动发现并修复的缺陷（TDD：先复现后修复）

1. **迁移 PG 方言缺陷 ×3**（离线测试从未覆盖真实 asyncpg + PG 反射）：
   - `evidence_command`：`format('%I.%I', ..., :table_name)` 变参上下文中绑定参数类型不可推断 → `AmbiguousParameterError`；`tgenabled`（PG `char`）经 asyncpg 返回 bytes，`str(b'O') != 'O'` 使 guard 匹配恒败 → `EVIDENCE_PACKAGE_GUARD_CONFLICT`。
   - `holdout_executions`：`_sql_matches` 假设“PostgreSQL keeps the authored shape”，实际 `pg_get_constraintdef` 把 `IN (...)` 重写为 `= ANY (ARRAY[... ::character varying]::text[])` → `HOLDOUT_EXECUTION_ACCESS_SCHEMA_CONFLICT`。
   - `approval_authority`：同款参数歧义 + `tgenabled` bytes + `trim(x)` 被反射为 `TRIM(BOTH FROM x)` 的 token 序列错位 → `APPROVAL_AUTHORITY_SCHEMA_CONFLICT`。
2. **harness 预期模型缺陷 ×2**：
   - `_fault_reached_phases` 假设取消后不再到达任何 checkpoint，与生产 `finally` 清理语义（完成 durable release 后再抛出 CancelledError）矛盾 → `POSTGRES_ACCEPTANCE_FAULT_REPORT_INVALID`；离线测试用同一 helper 构造 fixture 故自洽未暴露。
   - terminated 场景 finally 对已被 SIGTERM 的 leader 共享 Event 调用 `set()`：leader 死亡瞬时可持有 Event 内部条件信号量（macOS 无 robust semaphore）→ 锁永久泄漏 → 父进程同步 `set()` 死锁（两次运行均复现；`sample` 采样定位主线程阻塞于 `_multiprocessing.SemLock.acquire`）。修复为不触碰该原语（kill 路径已有审计退出码 + `_stop_two_process_workers` 兜底）。

修复后离线回归：`tests/market_data_platform/test_postgres_acceptance_harness.py` 33 passed；全量 `tests/market_data_platform tests/test_config.py` 1176 passed、0 failed（2026-09-18）；目标 Ruff 全绿。
