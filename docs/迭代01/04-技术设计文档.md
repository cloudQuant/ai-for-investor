## 1. 设计目标

本文档定义 `ai-for-investor` MVP 的技术方案，目标是在控制复杂度的前提下，为世界一流 AI 交易与投资社区建立可持续扩展的工程底座。

设计目标：

1. 支持博客、论坛、工具、项目发现和后台管理的 MVP 交付。
2. 保障金融内容和工具运行的安全边界。
3. 支持 SEO、内容分发和长期自然流量增长。
4. 支持异步任务、可观测性、备份和回滚。
5. 保持模块化单体，避免过早微服务化。
6. 支持论坛统一 UI 设计系统和多个可切换主题。

## 4. 模块设计

### 4.1 Auth Module

职责：

1. 用户注册、邮箱验证、登录、退出、重置密码。
2. 角色和权限校验。
3. 登录限流和认证审计。

核心实体：

1. users。
2. roles。
3. user_roles。
4. email_verification_tokens。
5. password_reset_tokens。

关键设计：

1. 密码使用 Argon2 或 bcrypt。
2. 邮箱验证和重置密码 token 存储哈希值，不存明文 token。
3. 后台管理员登录采用更严格限流。
4. 登录态可选择 HttpOnly Cookie Session 或 JWT + Refresh Token。

### 4.2 Blog Module

职责：

1. 文章列表、详情、分类、标签、搜索。
2. 后台文章创建、编辑、预览、发布、下线。
3. Markdown 渲染、SEO 元信息、RSS。

核心实体：

1. blog_posts。
2. categories。
3. tags。
4. tag_relations。
5. content_versions。

关键设计：

1. 文章使用 slug 作为公开 URL 标识。
2. published 状态文章才可被游客访问。
3. Markdown 渲染必须经过 XSS 清洗。
4. 发布文章时生成或更新 sitemap/RSS。

### 4.3 Forum Module

职责：

1. 帖子列表、详情、发帖、编辑、删除。
2. 回复、举报、置顶、加精、锁定、隐藏。
3. 新用户频率限制和基础反垃圾。

核心实体：

1. forum_categories。
2. forum_threads。
3. forum_replies。
4. forum_reports。
5. user_reputation。

关键设计：

1. MVP 仅支持一级回复。
2. 删除采用软删除或隐藏。
3. 版主和管理员操作写入 audit_logs。
4. 锁定帖子不允许继续回复。

### 4.4 Tool Module

职责：

1. 工具列表和详情。
2. 工具 manifest 管理。
3. 工具任务创建、排队、执行、结果展示。
4. 工具运行日志、资源记录和失败追踪。

核心实体：

1. tools。
2. tool_manifests。
3. tool_jobs。
4. tool_job_payloads。
5. tool_audit_logs。

关键设计：

1. 工具必须由管理员白名单配置。
2. 用户只能填写 manifest 允许的参数。
3. 工具任务异步执行，不阻塞 Web 请求。
4. 工具容器默认只读文件系统。
5. 默认禁止出站网络，特殊工具按域名白名单审批。
6. 高风险工具只能使用 external 或 document 模式。

### 4.5 Discovery Module

职责：

1. GitHub 项目采集。
2. 项目去重、快照和评分。
3. 人工审核和周报素材池。
4. 项目库公开展示。

核心实体：

1. discovery_keywords。
2. github_project_snapshots。
3. open_source_projects。
4. project_scores。
5. weekly_report_candidates。

关键设计：

1. GitHub API token 通过环境变量配置。
2. 采集任务支持失败重试和断点续跑。
3. 自动评分只作为初筛，发布必须人工审核。
4. 项目历史快照用于趋势分析。

### 4.6 Admin Module

职责：

1. 用户、文章、论坛、工具、项目发现管理。
2. 指标看板。
3. 审计日志查询。
4. 系统配置。

关键设计：

1. 所有后台接口必须校验管理员/版主/作者权限。
2. 高风险操作必须记录操作者、对象、动作、时间和 request_id。
3. 后台接口路径统一使用 `/api/v1/admin/*`。

### 4.7 UI Theme Module

职责：

1. 管理论坛和全站前台主题。
2. 提供主题 token、组件语义和主题切换入口。
3. 读取和保存游客、本地、cookie、登录用户偏好。
4. 在 Nuxt SSR 阶段注入首屏主题，避免明显主题闪烁。

核心实体：

1. user_preferences。
2. theme_presets。
3. frontend theme tokens。

关键设计：

1. 所有主题基于 `07-论坛UI设计规范与主题系统.md` 定义的语义 token。
2. 组件只使用 `--color-bg`、`--color-surface`、`--color-primary`、`--color-danger` 等语义变量，不直接写具体色值。
3. 默认主题为 `fintech-trust-light`。
4. MVP 至少实现 `fintech-trust-light` 和 `terminal-agent-dark`。
5. 推荐预置 `minimal-focus` 和 `research-docs-light`，如果开发排期不足，可作为 P1 开关隐藏。
6. 登录用户主题偏好通过 `/api/v1/users/me/preferences` 保存。
7. 未登录用户主题偏好通过 `localStorage` 和 cookie 保存。
8. 服务端渲染优先读取 cookie 中的 `ui_theme`。

## 10. 安全设计

### 10.1 风险与措施总览

| 风险 | 设计措施 |
|---|---|
| XSS | Markdown 渲染清洗，限制 HTML；CSP 头限制 inline script |
| CSRF | Cookie 模式下启用 CSRF token；Token 模式下校验 Authorization |
| SQL 注入 | 全部使用 SQLAlchemy ORM 或参数化查询，禁止字符串拼接 SQL |
| NoSQL 注入 | Motor 查询禁止接受用户输入作为操作符（如 `$gt`、`$ne`），查询参数必须白名单校验 |
| 越权 | 后端统一权限依赖，资源所有者校验 |
| 账号枚举 | 登录、注册、忘记密码统一返回模糊提示，不区分"用户不存在"和"密码错误" |
| 暴力破解 | 登录、注册、邮件接口限流；连续失败 5 次后锁定 15 分钟 |
| SSRF | GitHub 采集和外部 URL 处理校验目标非内网 IP（10.x、172.16-31.x、192.168.x、127.x、169.254.x），限制跳转 <= 3 次，禁止非 HTTP(S) 协议 |
| 工具逃逸 | 容器隔离、只读文件系统、资源限制、网络限制（详见 10.4） |
| 敏感信息泄露 | 日志脱敏、密钥环境变量管理、敏感信息扫描、生产禁止返回堆栈和 DB 错误详情 |
| 供应链风险 | lockfile 锁定依赖版本、Dependabot/Trivy 漏洞扫描、镜像扫描、license 检查 |
| DDoS | 接入腾讯云 WAF 或 CDN 防护；单 IP 全局速率上限 |
| 会话劫持 | Cookie 设置 Secure + HttpOnly + SameSite=Lax；空闲超时 30 分钟、绝对超时 24 小时 |

### 10.2 HTTP 安全响应头

生产环境 Nginx 或 FastAPI 中间件必须配置以下响应头：

```text
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https://cos.example.com; connect-src 'self'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
X-XSS-Protection: 0
```

CSP 策略说明：

1. `script-src 'self'` 禁止 inline script，防止 XSS 执行。
2. `frame-ancestors 'none'` 防止点击劫持。
3. `img-src` 允许 COS 域名用于图片 CDN。
4. MVP 阶段如果使用 Nuxt SSR inline script，需要配置 `nonce` 机制。

### 10.3 CORS 策略

```python
# FastAPI CORS 配置示例
ALLOWED_ORIGINS = [
    "https://ai-for-investor.com",
    "https://www.ai-for-investor.com",

# 开发环境追加 http://localhost:3000
```

### 10.4 工具容器安全加固

在技术设计 7.3 基础上，补充以下安全控制：

1. 容器以非 root 用户运行（`USER 1000:1000`）。
2. 启用 `--no-new-privileges` 防止容器内提权。
3. 启用 Docker 默认 seccomp profile。
4. 禁用 `--privileged` 模式。
5. tmpfs 挂载限制大小（建议 100MB）。
6. 禁止挂载宿主机 Docker socket。
7. 容器镜像必须使用固定 tag（禁止 `latest`），建议启用镜像签名验证（Cosign/Notary）。
8. 容器内禁止 `SYS_ADMIN`、`NET_RAW` 等危险 capabilities。

```yaml
# Docker run 安全参数示例
security_opt:
  - no-new-privileges:true
  - seccomp:default
cap_drop:
  - ALL
read_only: true
tmpfs:
  /tmp:
    size: 100m
user: "1000:1000"
```

### 10.5 认证与会话安全

1. 密码哈希：Argon2id（首选）或 bcrypt，cost factor >= 12。
2. 密码策略：最少 8 位，包含大小写字母和数字，禁止 top-10000 常见弱密码。
3. 邮箱验证 token：使用 `secrets.token_urlsafe(32)` 生成，存储 SHA-256 哈希值，有效期 24 小时。
4. 密码重置 token：同上，有效期 1 小时，使用后立即失效。
5. 登录会话超时：空闲 30 分钟自动过期，绝对有效期 24 小时。
6. 管理员登录：必须二次验证（MVP 采用邮箱验证码，后续升级 TOTP）。
7. 管理员接口建议限制来源 IP 白名单（生产环境通过 Nginx 或 WAF 配置）。
8. 如果选择 JWT 方案：
   - 必须指定 `algorithm: HS256` 或 `RS256`，禁止 `none` 算法。
   - Access token 有效期 15 分钟，Refresh token 有效期 7 天。
   - Refresh token 必须支持轮换（rotation），使用后旧 token 立即失效。
   - Token 禁止存储在 localStorage（易受 XSS 攻击），使用 HttpOnly cookie。

### 10.6 数据安全

1. 数据库连接必须使用 TLS 加密传输。
2. MySQL、MongoDB 必须启用认证，禁止匿名访问。
3. Redis 必须设置 AUTH 密码，并通过 `rename-command` 禁用 `KEYS`、`FLUSHALL`、`FLUSHDB`、`CONFIG`、`DEBUG` 等危险命令。
4. 数据库备份文件必须加密存储（AES-256 或 GPG），传输使用 TLS。
5. 生产数据库建议启用磁盘加密（腾讯云 CBS 加密）。
6. 用户 PII 字段（email、IP、username）在日志中必须脱敏（如 `u***@example.com`）。
7. 日志写入前必须转义用户输入中的换行符（`\n`、`\r`）和控制字符，防止日志注入。

### 10.7 文件上传安全

1. 文件类型白名单：仅允许 `image/png`、`image/jpeg`、`image/gif`、`image/webp`。
2. 文件类型校验：必须检查文件 magic bytes（文件头），不能仅依赖 Content-Type 或扩展名。
3. 文件大小限制：单文件 <= 5MB（可配置）。
4. 文件名处理：重命名为 UUID，禁止保留原始文件名路径。
5. 上传文件必须存储在腾讯云 COS，通过独立域名（如 `cdn.ai-for-investor.com`）提供，不得与主站同源。
6. COS bucket 策略禁止列举，仅允许读取已知路径。

### 10.8 内容安全

1. 论坛和博客中用户提交的外部链接必须添加 `rel="noopener noreferrer nofollow"` 属性。
2. Markdown 渲染后 HTML 必须经过白名单清洗（如 `bleach` 或 `sanitize-html`），只允许安全标签和属性。
3. 用户头像和内容中引用的外部图片建议通过图片代理加载，防止 referrer 泄露和追踪像素。
4. 论坛重复内容检测必须包含 URL spam 检测（批量相同链接发帖）。

### 10.9 错误处理安全

1. 生产环境所有未捕获异常返回统一 500 错误格式，包含 `request_id`，不包含堆栈跟踪和内部细节。
2. Nginx 配置移除或覆盖 `Server` 头（`server_tokens off`）。
3. FastAPI 移除 OpenAPI `/docs` 和 `/redoc` 在生产环境的公开访问（仅内网或认证后访问）。
4. 数据库错误信息不得原样返回给客户端。

### 10.10 安全事件响应

必须建立安全事件响应流程文档，包含：

1. 事件分级：P0（数据泄露、资金相关）、P1（越权访问、注入攻击）、P2（限流触发、异常登录模式）。
2. 通知机制：P0 事件 15 分钟内通知负责人，P1 事件 1 小时内。
3. 处置流程：隔离 -> 取证 -> 修复 -> 验证 -> 恢复。
4. 事后复盘：72 小时内完成事件报告，更新防护策略。
5. 联系方式：安全负责人、运维负责人、法务联系人清单。

### 10.11 基础设施安全

1. 腾讯云 CVM 安全组：仅开放 80/443（HTTP/HTTPS），SSH 限制来源 IP。
2. 数据库端口（3306、27017、6379）仅允许内网访问，禁止公网暴露。
3. SSH 登录禁用密码认证，仅允许密钥认证。
4. 操作系统开启自动安全更新。
5. Docker daemon 不暴露 TCP socket，使用 Unix socket。

## 11. 可观测性设计

### 11.1 日志

日志格式为 JSON，至少包含：

1. timestamp。
2. level。
3. request_id。
4. user_id。
5. route。
6. status_code。
7. latency_ms。
8. error_code。
9. job_id。

### 11.2 指标

1. API QPS。
2. API P95/P99。
3. 5xx 错误率。
4. 队列长度。
5. 工具任务成功率。
6. 邮件发送成功率。
7. 数据库慢查询。
8. 服务器 CPU、内存、磁盘。

### 11.3 告警

1. 5xx 错误率超阈值。
2. 队列积压超阈值。
3. 工具任务失败率升高。
4. 邮件发送失败率升高。
5. 数据库连接异常。
6. 磁盘空间不足。

## 13. 架构演进

MVP 坚持模块化单体。当满足以下条件时再考虑拆分：

1. 工具任务消耗影响主站稳定性。
2. GitHub 采集或搜索成为独立扩展瓶颈。
3. 推荐、搜索或 RAG 需要独立部署。
4. 团队扩大，需要独立发布节奏。
5. 企业私有部署或商业化要求独立 SLA。

## 14. 关键 ADR 建议

MVP 阶段建议记录以下 ADR：

1. 是否使用 Nuxt 3 而不是 Vite SPA。
2. 登录态采用 Cookie Session 还是 JWT。
3. Worker 选择 Arq、Celery 还是 RQ。
4. 工具任务容器运行方案。
5. MySQL 与 MongoDB 的数据边界。
6. 搜索 MVP 使用 MySQL fulltext 还是独立搜索引擎。
7. 论坛主题系统采用自研 CSS Variables 还是 UI 库主题能力。
8. MVP 首批主题实现 2 个还是 4 个。
