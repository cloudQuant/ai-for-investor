## 1. 项目背景

`ai-for-investor.com` 已具备独立域名，项目目标是建设一个聚焦 AI 在交易与投资领域应用的社区型网站。

AI 与交易、投资结合正在快速发展，开源生态中已经出现大量金融大模型、量化研究平台、AI Agent、回测工具、交易机器人、投资组合分析和数据分析项目。但这些内容分散在 GitHub、论文、博客、社交媒体和英文社区中，普通交易者、投资者、量化学习者和 AI 开发者缺少一个可信、可理解、可复现、可讨论的入口。

`ai-for-investor` 的业务机会不是直接做券商、交易所、实盘交易或投资顾问平台，而是成为 AI 交易与投资开源项目、教程、工具体验和社区讨论的高质量聚合平台。

---

## 2. 愿景与定位

### 2.1 长期愿景

打造世界一流的 AI 交易与投资社区，沉淀高质量用户、内容、工具和讨论，成为 AI 交易与投资方向开发者、量化研究者、交易者和投资者的首选实践社区。

### 2.2 MVP 定位

MVP 阶段定位为：

```text
AI 交易与投资开源项目精选 + 实践教程 + 轻量工具体验 + 社区讨论
```

MVP 不定位为：

1. 真实交易平台。
2. 投资建议平台。
3. 券商或交易所接入平台。
4. 任意用户代码托管执行平台。
5. 以收益承诺为核心的策略排行榜平台。

## 5. 核心业务场景

### 5.1 游客阅读和注册

```text
搜索/外部链接 -> 进入博客文章 -> 查看项目卡片或工具说明 -> 阅读相关论坛讨论 -> 注册
```

业务价值：建立流量入口和注册转化。

### 5.2 注册用户参与社区

```text
注册 -> 邮箱验证 -> 完善资料 -> 收藏文章 -> 发帖/回复 -> 参与工具反馈
```

业务价值：让内容消费转化为社区沉淀。

### 5.3 内容运营发布周报

```text
GitHub 项目发现 -> 项目评分 -> 编辑筛选 -> 生成周报素材 -> 发布博客 -> 关联讨论帖
```

业务价值：形成稳定内容供给和社区话题来源。

### 5.4 用户使用精选工具

```text
登录 -> 查看工具详情 -> 填写白名单参数 -> 创建工具任务 -> 查看结果 -> 分享或反馈
```

业务价值：形成与普通内容站不同的实践体验。

## 6. MVP 业务范围

### 6.1 P0 必须包含

| 模块 | 范围 |
|---|---|
| 基础站点 | 首页、导航、响应式布局、SEO 基础、免责声明 |
| 用户系统 | 注册、邮箱验证、登录、退出、忘记密码、用户资料 |
| 权限系统 | 游客、注册用户、作者、编辑、版主、管理员 |
| 博客 | 公开阅读、分类、标签、搜索、后台发布、草稿、下线 |
| 论坛 | 浏览、发帖、回复、编辑、删除、举报、管理 |
| 体验设计 | 论坛统一 UI 设计规范、多主题切换、用户主题偏好 |
| 工具区 | 工具列表、详情、登录后使用、任务记录、受限 Demo |
| 项目发现 | GitHub 采集、项目评分、人工审核、周报素材池 |
| 管理后台 | 用户、文章、论坛、标签、工具、项目发现管理 |
| 安全合规 | 免责声明、用户协议、隐私政策、限流、审计日志 |
| 数据运营 | 基础埋点、注册漏斗、内容阅读、工具使用指标 |

### 6.2 P1 可延后

1. 第三方 OAuth 登录。
2. 积分、等级、徽章。
3. 站内通知和 Newsletter 自动化。
4. 工具结果分享页。
5. 专题页、标签页 SEO 增强。
6. 高级搜索。
7. 用户主页和贡献展示。

### 6.3 明确不做

1. 不提供投资建议或收益承诺。
2. 不接入真实券商账户、交易所账户或用户资金。
3. 不允许用户上传任意策略代码在线执行。
4. 不以回测收益作为默认排行榜。
5. 不在 MVP 中做复杂推荐算法。

## 7. 成功指标

### 7.1 北极星指标

每周有效活跃用户数：一周内完成阅读深度行为、注册、收藏、发帖、回复、使用工具、订阅周报、提交项目推荐等至少一种有效行为的用户数。

### 7.2 MVP 上线 4 周目标

| 指标 | 目标 |
|---|---:|
| 发布博客 | >= 10 篇 |
| AI 交易与投资周报 | >= 4 期 |
| 注册用户 | >= 100 |
| 邮箱验证率 | >= 60% |
| 发帖/回复用户 | >= 20 |
| 工具使用用户 | >= 30 |
| 工具任务成功率 | >= 90% |
| 周活跃注册用户 | >= 50 |
| 7 日注册用户留存 | >= 25% |
| 严重安全事故 | 0 |

## 8. 业务约束

| 约束 | 说明 |
|---|---|
| 技术栈 | Vue/Nuxt + TypeScript、FastAPI、MySQL、MongoDB、Redis、GitHub Actions、腾讯云 |
| 合规边界 | 教育研究用途，不构成投资建议 |
| 工具安全 | 白名单工具、容器隔离、资源限制、人工审核 |
| 内容质量 | 项目评分、编辑审核、风险提示、来源引用 |
| SEO | 博客和项目详情页应具备长期自然流量能力 |
| 成本 | MVP 首批工具应优先 CPU 可运行、低资源、低依赖复杂度 |

---

## 9. 主要风险

| 风险 | 等级 | 应对 |
|---|---|---|
| 金融合规风险 | 高 | 明确免责声明，禁止荐股和收益承诺 |
| 工具执行安全风险 | 高 | 沙箱、白名单、资源配额、人工审核 |
| 社区冷启动风险 | 中 | 通过博客、周报和种子讨论拉动 |
| 内容质量不足 | 高 | 建立项目评分和文章模板 |
| SEO 起量慢 | 中 | 优先 SSR/预渲染、RSS、结构化数据 |
| 技术范围过大 | 中 | MVP 坚持模块化单体，不做过早平台化 |

---

## 10. 业务验收条件

MVP 进入公测前必须满足：

1. 游客可以稳定浏览首页、博客、论坛和工具说明。
2. 用户可以完成注册、邮箱验证、登录和退出。
3. 已有至少 10 篇可公开传播的种子内容。
4. 已有至少 20 个种子论坛话题。
5. 已有至少 3 个工具说明或轻量 Demo。
6. GitHub 项目发现和周报素材池可运行。
7. 管理后台可以管理用户、内容、论坛和工具。
8. 全站展示金融风险免责声明。
9. 工具运行不会接触真实资金或用户交易账户。
10. 上线验收文档中的 P0 项全部通过。
