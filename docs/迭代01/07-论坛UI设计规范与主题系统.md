## 1. 设计目标

论坛是 `ai-for-investor` 社区沉淀的核心场景，必须在视觉、交互和组件层面形成统一体验。

本设计规范参考 `VoltAgent/awesome-design-md` 中 DESIGN.md 的组织方式，吸收其“用文本定义视觉系统、组件规范和设计约束”的方法，但不直接复制任何具体品牌视觉资产。

目标：

1. 论坛所有页面具备统一的视觉语言。
2. 支持多个预设风格主题切换。
3. 主题切换不影响信息结构、交互路径和可访问性。
4. 所有主题基于同一套设计 token 和组件语义实现。
5. 后续博客、工具区、项目库可复用同一主题系统。

---

## 2. 设计原则

1. 统一结构：论坛列表、详情、编辑器、回复、举报、管理操作使用同一套布局和组件。
2. 内容优先：视觉风格服务于阅读、讨论和信息判断，不抢占内容注意力。
3. 金融可信：默认主题应传达专业、克制、可信，不使用夸张收益暗示。
4. 开发者友好：代码、模型、项目、数据讨论应具备清晰的技术阅读体验。
5. 可切换但不割裂：主题只改变色彩、表面、阴影、边框和局部动效，不改变核心交互。
6. 可访问性优先：所有主题必须满足基础对比度、键盘可达和焦点可见要求。

## 4. MVP 主题列表

### 4.1 `fintech-trust-light`

默认主题。

定位：金融可信、清爽、适合新用户和公共内容传播。

视觉特征：

1. 浅色背景。
2. 蓝色主按钮和关键链接。
3. 绿色用于成功、验证、正向状态。
4. 红色只用于风险、删除、警告。
5. 卡片边框轻，阴影弱，留白充足。

### 4.2 `terminal-agent-dark`

开发者暗色主题。

定位：AI Agent、工具、代码和量化开发讨论氛围。

视觉特征：

1. 深黑或近黑背景。
2. 绿色/青绿色作为强调色。
3. 代码块、命令、工具状态具备终端感。
4. 卡片使用细边框和轻微发光，不使用厚重阴影。
5. 适合夜间阅读和开发者长时间使用。

### 4.3 `minimal-focus`

极简专注主题。

定位：降低视觉噪音，提高论坛信息浏览效率。

视觉特征：

1. 中性色为主。
2. 低饱和紫色或蓝紫色作为强调色。
3. 列表密度略高。
4. 边框清晰，阴影极少。
5. 适合高频用户、版主和重度阅读用户。

### 4.4 `research-docs-light`

研究文档主题。

定位：长内容、教程、项目复盘、研究型讨论。

视觉特征：

1. 温和浅色背景。
2. 绿色/青色强调。
3. 正文行高更舒适。
4. 引用、代码、公式、链接样式更突出。
5. 适合长帖和知识库式内容沉淀。

## 5. 设计 Token

所有主题必须通过语义 token 实现，禁止在组件内硬编码主题色。

### 5.1 色彩 Token

| Token | 含义 |
|---|---|
| `--color-bg` | 页面背景 |
| `--color-surface` | 卡片、弹窗、侧栏背景 |
| `--color-surface-muted` | 次级表面 |
| `--color-border` | 默认边框 |
| `--color-border-strong` | 强边框或激活边框 |
| `--color-text` | 主文本 |
| `--color-text-muted` | 次级文本 |
| `--color-text-subtle` | 辅助文本 |
| `--color-primary` | 主操作、链接、选中态 |
| `--color-primary-hover` | 主操作 hover |
| `--color-success` | 成功、验证 |
| `--color-warning` | 警告、风险提醒 |
| `--color-danger` | 删除、封禁、违规 |
| `--color-code-bg` | 代码块背景 |
| `--color-focus-ring` | 键盘焦点 |

### 5.2 字体 Token

| Token | 含义 |
|---|---|
| `--font-sans` | 界面字体 |
| `--font-mono` | 代码、命令、数据字体 |
| `--font-size-xs` | 辅助信息 |
| `--font-size-sm` | 次级正文 |
| `--font-size-md` | 默认正文 |
| `--font-size-lg` | 小标题 |
| `--font-size-xl` | 页面标题 |

### 5.3 间距和圆角 Token

| Token | 含义 |
|---|---|
| `--space-1` ~ `--space-8` | 统一间距尺度 |
| `--radius-sm` | 小组件圆角 |
| `--radius-md` | 卡片圆角 |
| `--radius-lg` | 弹窗、大卡片圆角 |
| `--shadow-card` | 卡片阴影 |
| `--shadow-popover` | 浮层阴影 |

## 6. 论坛组件规范

### 6.1 Forum Layout

论坛基础布局包括：

1. 顶部导航。
2. 左侧或顶部分类导航。
3. 主内容区。
4. 右侧趋势、规则、热门标签或推荐工具区域。
5. 移动端折叠为单列布局。

### 6.2 Thread List Item

帖子列表项必须统一展示：

1. 标题。
2. 分类和标签。
3. 作者头像和名称。
4. 最后回复时间。
5. 浏览数、回复数、收藏数。
6. 状态标识：置顶、加精、锁定、已解决、风险提示。

不同主题只能改变视觉表达，不改变信息字段。

### 6.3 Thread Detail

帖子详情必须统一展示：

1. 标题区域。
2. 作者信息。
3. 正文。
4. 标签和分类。
5. 操作区：回复、收藏、举报、编辑、删除、管理。
6. 回复列表。
7. 风险提示和社区规则入口。

### 6.4 Editor

发帖和回复编辑器必须支持：

1. Markdown 输入。
2. 预览。
3. 代码块样式。
4. 风险提示。
5. 保存草稿的后续扩展空间。

### 6.5 Moderation Components

管理和治理组件必须在所有主题中保持高识别度：

1. 举报按钮。
2. 锁定状态。
3. 隐藏状态。
4. 删除确认弹窗。
5. 封禁或警告提示。

危险操作必须使用 `--color-danger`，不能因主题变化降低识别度。

## 7. 主题切换交互

### 7.1 入口

MVP 主题切换入口建议放在：

1. 顶部导航用户菜单。
2. 用户中心外观设置。
3. 未登录用户可在顶部导航切换临时主题。

### 7.2 持久化

1. 未登录用户：保存到 `localStorage` 和 cookie。
2. 登录用户：保存到用户偏好字段，同时写入 cookie。
3. 服务端渲染时优先读取 cookie，避免首屏主题闪烁。

### 7.3 默认规则

1. 默认主题为 `fintech-trust-light`。
2. 如果用户系统偏好为 dark，且没有显式选择，可推荐 `terminal-agent-dark`，但不强制切换。
3. 用户显式选择优先级高于系统偏好。

---

## 8. 响应式要求

| 断点 | 要求 |
|---|---|
| Mobile | 单列布局，分类折叠，主题切换入口保留在菜单中 |
| Tablet | 主内容 + 折叠侧栏，帖子卡片保留核心信息 |
| Desktop | 主内容 + 侧栏，展示完整统计、热门标签和社区规则 |

触控目标不小于 44px，主题切换控件必须可键盘操作。

---

## 9. 可访问性要求

1. 文本与背景对比度至少满足 WCAG AA。
2. 所有主题必须提供明显 focus ring。
3. 不只依赖颜色表达状态，必须同时使用图标、文字或标签。
4. 支持 `prefers-reduced-motion`。
5. 主题切换后焦点不丢失。
6. 深色主题下代码、链接、危险提示必须清晰可读。

---

## 10. 禁止事项

1. 禁止在不同论坛页面使用不同设计语言。
2. 禁止为每个页面单独写一套颜色。
3. 禁止直接复制第三方品牌的 logo、专属字体、商标化图形或完整视觉资产。
4. 禁止主题切换改变功能可见性或权限规则。
5. 禁止低对比度文本和不可见焦点态。
6. 禁止在金融内容中使用暗示收益的视觉元素，例如暴涨箭头、金币雨、收益炫光。

---

## 11. 设计验收标准

1. 论坛列表、详情、发帖、回复、举报、管理操作在同一主题下视觉一致。
2. 至少提供 3 个可切换主题，推荐实现 4 个预设主题。
3. 主题切换后无需刷新即可生效。
4. 刷新页面后主题保持不变。
5. SSR 首屏不出现明显主题闪烁。
6. 所有主题下核心按钮、链接、危险操作、锁定/置顶/加精状态可识别。
7. 移动端可以正常切换主题。
8. 主题系统可复用于博客、工具区和项目库。
