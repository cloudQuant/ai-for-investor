## 1. 产品概述

`ai-for-investor` 是面向交易者、投资者、量化研究者和 AI 开发者的 AI 交易与投资开源项目精选、实践教程、工具体验与社区讨论平台。

MVP 产品由六个核心部分组成：

1. 基础站点与首页。
2. 用户与权限。
3. 博客与内容 CMS。
4. 论坛与社区治理。
5. 工具区。
6. GitHub 项目发现与周报工作流。

---

## 2. 产品原则

1. 内容优先：先通过高质量内容建立信任和流量。
2. 社区沉淀：每篇重点内容都应引导用户讨论。
3. 工具可控：工具区只提供受限、低风险、白名单体验。
4. 风险透明：所有交易与投资相关内容必须提示风险，不承诺收益。
5. SEO 友好：博客、项目库、工具详情、论坛主题都应可被搜索发现。
6. 运营可管理：MVP 必须具备后台和审核能力。
7. 设计统一：论坛所有页面必须遵循统一 UI 设计系统，同时支持多个主题风格切换。

## 3. 角色与权限

| 角色 | 权限 |
|---|---|
| 游客 | 浏览首页、博客、论坛、工具说明、项目库 |
| 注册用户 | 发帖、回复、收藏、使用工具、提交项目推荐 |
| 作者 | 发布和管理自己的博客文章 |
| 编辑 | 审核项目发现评分、管理周报素材池、审核内容质量 |
| 版主 | 管理论坛主题、回复、举报和违规内容 |
| 管理员 | 管理用户、文章、论坛、工具、项目发现、系统配置 |

权限原则：

1. 博客公开可读。
2. 论坛和工具说明公开可看。
3. 发帖、回复、使用工具、发布博客必须注册并完成邮箱验证。
4. 编辑角色聚焦内容审核和项目发现，不具备用户管理和系统配置权限。
5. 管理后台必须进行角色校验和审计记录。

## 5. 核心用户路径

### 5.1 游客路径

```text
首页 -> 阅读精选博客 -> 查看项目详情 -> 查看关联讨论 -> 注册
```

### 5.2 注册用户路径

```text
注册 -> 邮箱验证 -> 登录 -> 收藏文章/发帖/回复 -> 使用工具 -> 查看使用记录
```

### 5.3 内容运营路径

```text
后台登录 -> 查看采集项目 -> 编辑评分 -> 加入周报素材池 -> 发布文章 -> 关联讨论帖
```

### 5.4 管理员路径

```text
后台登录 -> 管理用户/内容/帖子/工具 -> 处理举报 -> 查看指标 -> 执行运营动作
```

### 9.1 论坛 UI 主题需求

论坛 UI 设计以 `07-论坛UI设计规范与主题系统.md` 为准。MVP 推荐提供以下主题：

| 主题 | 定位 | 优先级 |
|---|---|---|
| `fintech-trust-light` | 默认主题，金融可信、清爽、适合公共传播 | P0 |
| `terminal-agent-dark` | 开发者暗色主题，适合 AI Agent、工具和代码讨论 | P0 |
| `minimal-focus` | 极简专注主题，适合高频阅读和版主管理 | P1 |
| `research-docs-light` | 研究文档主题，适合教程、长帖和项目复盘 | P1 |

产品要求：

1. 论坛列表页、详情页、发帖页、回复组件、举报弹窗、管理操作必须在同一主题下视觉一致。
2. 主题切换入口必须对游客和登录用户都可见。
3. 未登录用户主题偏好保存到本地；登录用户主题偏好保存到用户偏好。
4. 刷新页面后应保持用户选择的主题。
5. 主题切换不能降低危险操作、锁定、置顶、加精、举报等状态识别度。
6. 主题设计可参考 `VoltAgent/awesome-design-md` 的 DESIGN.md 结构和风格抽象，但不能直接复制第三方品牌资产。

## 14. 产品验收原则

1. 所有 P0 页面必须可访问，且具备加载、空状态、错误状态。
2. 所有 P0 写操作必须有权限校验。
3. 所有交易与投资相关内容必须有风险提示。
4. 未登录用户触发写操作时必须引导登录或注册。
5. 管理后台必须覆盖核心运营动作。
6. 工具区必须避免真实交易和任意代码执行。
7. SEO 基础能力必须在博客、项目库、工具详情页覆盖。
8. 论坛必须在统一设计系统下通过主题切换验收。
